# vecsvc — 分层近邻图向量检索服务（Go）

一个用纯 Go 实现的、面向「亿级向量 + 强过滤」场景的向量检索服务，包含仿真数据、
HNSW 分层近邻图索引、乘积量化（PQ）压缩、自适应过滤策略、删除/更新与图修复，
以及一个可观测召回率/时延曲线、图搜索路径和策略选择的 Web 仪表盘。

## 解决的问题

传统检索库「先取 top-1000 再过滤」在严格过滤条件下会过滤到一个结果都不剩；
而「先过滤再全量暴力算」在宽条件下又太慢。本服务按过滤**选择率（selectivity）**
自适应选择策略，并把向量检索与过滤谓词下推到图遍历过程中。

## 架构与模块

```
cmd/vecsvc           CLI 入口：bench（验收基准）/ serve（HTTP + 仪表盘）
internal/synth       仿真嵌入向量（明显簇结构）+ 标签/数值属性 + 查询生成
internal/hnsw        分层近邻图（HNSW）：贪心下降、有界候选队列、启发式选邻居、软删除/重建
internal/pq          乘积量化：k-means 子空间码本 + ADC 非对称距离表
internal/store       编排层：倒排候选集、三档过滤策略、PQ/原始距离源、暴力基线、增删改
internal/bench       验收基准：召回/时延、ef 扫描、PQ 对比、删除波、构建与内存成本
internal/server      HTTP API + 内嵌 Web 仪表盘（原生 JS，无外部依赖，离线可用）
```

### 1. 分层近邻图（HNSW）

- 每个节点按指数衰减的层级分布落到某一层，**高层稀疏、底层稠密**；上层是长距离「快速路」。
- 插入时从顶层入口**贪心下降**，在目标层用大小为 `efConstruct` 的有界候选队列搜索邻居。
- 邻居选择用 **HNSW 启发式（algorithm 4）**：候选只有在比它到任一已选邻居更近于查询时才保留，
  避免簇内「枢纽节点」和单向连边，保证图的连通性与多样性；双向连边并按层做度数裁剪
  （层 0 上限 `Mmax0=2M`，上层上限 `M`）。
- 查询从顶层入口逐层贪心下降（上层 `ef=1`），底层用大小可调的有界候选队列（`ef`）做束搜索。
  `ef` 越大召回越高、时延越长——这就是召回/时延旋钮。

### 2. 有界候选队列

候选集 C 用距离最小堆（总弹最近的未访问节点），动态结果集 W 用距离最大堆并限制在 `ef`
（满了就弹最远的）。当 C 的最近候选已远于 W 的第 ef 个结果时提前终止。

### 3. 自适应过滤策略（按选择率）

| 选择率 | 策略 | 行为 |
|---|---|---|
| ≥ 8%（宽） | `graph_relaxed` | 图遍历时**经过但不返回**不满足条件的节点——它们继续充当路由骨架 |
| 0.5%–8%（中） | `hybrid` | 先走放松图搜索；若取不到 k 个匹配（匹配点成孤岛），在候选子集上暴力兜底 |
| ≤ 0.5%（严） | `brute_force` | 直接在满足条件的子集上暴力算；标签条件走倒排表，纯数值条件走谓词全扫 |

阈值在 `store.DefaultThresholds()`，可按数据分布调整。倒排表为 tenant/category 维护。

### 4. 删除与更新

- 删除是**软删除（墓碑标记）**，搜索跳过墓碑，删除本身 O(1)。
- 带**滞后（hysteresis）的图修复**：自上次重建后新增墓碑达到「存活节点 × 10%」才触发一次
  全图局部重建——存活节点保留原层级，重新执行插入连边与启发式裁剪，修复所有指向墓碑的边。
  快速路径 `RepairPending` 只读计数器，删除热路径零额外分配。
- 更新 = 旧 id 打墓碑 + 新行插入（属性沿用），边通过正常插入路径重建。

### 5. 乘积量化（PQ）

- 128 维向量切成 `m=16` 个 8 维子空间，每个子空间用 k-means 学 256 个质心，
  向量编码为 16 字节（原始 512 字节 → **32 倍压缩**）。质心数随训练样本自适应。
- 搜索用 **ADC（非对称距离计算）**：每个查询先建 `m×k` 的查询-质心距离表，
  编码距离退化为 m 次查表相加。
- 流程为 **PQ 粗排取 8×k 候选池 → 原始 float32 向量精排截断到 k**。

## 快速开始

```bash
go build ./...

# 验收基准（默认 20 万向量，输出 report.json 与控制台汇总）
go run ./cmd/vecsvc bench -n 200000 -queries 40 -out report.json

# 启动 HTTP 服务 + 仪表盘
go run ./cmd/vecsvc serve -n 100000 -addr :8080
# 浏览器打开 http://localhost:8080
```

### CLI 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `-n` | 200000(bench)/100000(serve) | 仿真向量条数 |
| `-queries` | 50 | 每个过滤选择率档位的查询数 |
| `-pqm` | 16 | PQ 子空间数（0 关闭 PQ） |
| `-pqsample` | 50000 | 训练 PQ 的采样向量数 |
| `-delete` | 0.30 | 删除波实验的删除比例 |
| `-out` | report.json | 基准 JSON 报告路径 |

## HTTP API

| 方法/路径 | 作用 |
|---|---|
| `GET /api/stats` | 索引规模、墓碑比例、平均度数、内存、PQ 压缩 |
| `GET /api/filters/cases` | 内置的各选择率过滤档位 |
| `POST /api/search` | 查询（`k`/`ef`/`use_pq`/`record_path`/`filter`/`query_seed`） |
| `GET /api/attrs?id=...` | 结果向量的标签/数值属性 |
| `POST /api/bench/run` | 在服务内触发一次基准，报告供仪表盘渲染 |
| `GET /api/report` | 取最近一次基准报告 |

## 仪表盘能看到什么

- **召回率 vs 过滤选择率**、**查询时延 vs 过滤选择率**两条曲线（精确 vs PQ）。
- **ef 候选队列大小的召回/时延取舍曲线**。
- 各选择率档位的明细表，含实际选用的**策略标签**（蓝=图放松 / 黄=混合 / 红=暴力）。
- 构建时间、插入吞吐、堆内存、PQ 压缩倍率；删除波前后召回变化与修复次数。
- 单次查询在图上的**搜索路径**（SVG：纵轴层级、横轴访问顺序，绿=满足、红=经过的不满足节点、蓝=顶层入口）。

## 规模与内存估算

仿真向量为 128 维 float32（每条 512 字节）。主要占用：

| 规模 N | 原始向量 | PQ 编码(m=16) | 图连边(约 20 边/节点, int32) | 粗估总内存 |
|---|---|---|---|---|
| 100 万 | 512 MiB | 16 MiB | ~80 MiB | ~0.7 GiB |
| 1000 万 | 5.1 GiB | 160 MiB | ~800 MiB | ~6.5 GiB |
| 1 亿 | 51 GiB | 1.6 GiB | ~8 GiB | ~60 GiB |

本机为 16 GiB 内存，默认/演示规模取 10 万–20 万；调大 `-n` 即可上量，
亿级需要相应内存或改用 mmap/分片（当前为单进程内存版）。代码所有大数组均为连续分配，
GC 压力可控。

## 仿真数据的真实性

- 向量：64 个宽分布的簇心 + 簇内高斯扰动（σ=0.6），具备真实嵌入的**明显簇结构**；
  相比高维 i.i.d. 均匀/正态（向量间几乎等距），更能反映近邻图的真实行为。
- 属性：tenant（32 档）、category（16 档）低基数标签，时间戳、价格数值属性。
- 查询：在某条向量上加小高斯抖动生成，保证有非平凡局部邻域；过滤档位从无过滤到
  约 0.05% 选择率，覆盖宽/中/严三个策略区。
- 真值：所有召回率都与并行暴力计算的真实近邻对比。
