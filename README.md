# vecsearch — 带过滤策略与乘积量化的分层近邻图向量检索服务

面向"几亿条几百维向量 + 严格过滤条件"场景的向量检索引擎。纯 Go 实现,
无外部依赖,内置仿真数据生成、HNSW 风格分层近邻图、乘积量化、
三策略过滤检索、软删除与局部图修复,以及可视化页面。

## 它解决的核心问题

朴素方案在带过滤的 ANN 检索里有两个失败模式:

- **先检索后过滤**: 先取 top-1000 再套过滤条件,严格条件过滤完所剩无几甚至为空;
- **先过滤后暴力**: 在满足条件的子集上全量算距离,宽条件下慢到不可用。

本引擎按过滤条件的**估计选择率**在三种策略间切换,兼顾召回与时延。

## 架构

```
cmd/vecsearch/       CLI 入口: bench(验收) / serve(可视化服务)
internal/sim/        仿真嵌入向量(GMM 簇结构) + 结构化属性 + 查询生成
internal/store/      列式存储、删除位图、倒排表、选择率估计与候选枚举
internal/pq/         乘积量化: 子空间 k-means、编码、ADC 距离表
internal/hnsw/       分层近邻图: 启发式选边、贪心下降、有界候选队列、局部修复
internal/index/      集成层: 三策略检索、PQ 粗排+精排、删除/更新、统计
internal/eval/       验收: 选择率档位、ef 曲线、PQ 对比、删除 sweep
internal/server/     HTTP API + 嵌入的可视化页面(原生 JS/SVG, 离线可用)
```

### 1. 分层近邻图 (HNSW)

- 节点按几何分布 `l = floor(-ln U / ln M)` 随机分层,高层稀疏、低层稠密;
- 插入时从顶层入口贪心下降定位,再在各层用**启发式邻居选择**连边:
  若候选到某已选邻居比到查询点更近,认为该方向已被覆盖而跳过,
  抑制团簇内冗余短边、保留方向多样性,选不满时用最近候选回填保证连通;
- 双向连接,邻居度超限时重新启发式剪枝(层 0 上限 `2M`,其余 `M`);
- 查询从顶层入口逐层贪心下降,底层在**有界候选队列 `ef`** 内做
  贪心最佳优先搜索。`ef` 是召回率与时延的主调节旋钮。

### 2. 三策略过滤检索

选择率由倒排表精确基数 + 数值列等频分位数估计(假设各条件近似独立):

| 选择率 | 策略 | 行为 |
|---|---|---|
| > 5% | `graph_filtered` | 图搜索中**跳过不满足的点但继续经过它们走**,连通性不被过滤切断 |
| 0.5%–5% | `graph_relaxed` | 候选队列 `ef×4` 对抗命中稀释;图结果不足 K 时用倒排枚举子集补搜 |
| ≤ 0.5% | `brute_force` | 倒排交集枚举满足条件的子集直接暴力,避免图搜索空转 |

阈值在 `index.Options` 中可调。

### 3. 乘积量化 (PQ)

- D 维向量切 M 个子空间,各做 Ks=256 质心 k-means,每子向量 1 字节编码,
  128 维向量从 512 字节压到 16 字节(32×);
- 三种距离模式:
  - `exact`: 全程原始向量精确距离;
  - `hybrid_pq`(工程默认): 图导航用精确距离保住路由,候选用 PQ 距离
    粗排截断到 `K×RerankMul`,再用原始向量精排;
  - `full_pq`: 全程 PQ 距离导航 + 原始向量精排,极限省内存场景。

### 4. 删除与更新

- 删除只打位图标记,不立即动图;累计删除比例超阈值(默认 10%)触发**局部修复**:
  摘除受影响节点连向删除点的边,以二度邻居为候选启发式补连,
  复杂度与局部邻域成正比,不重建全图;
- 修复只处理**新增**删除节点,已修复的不重复计算;
- 更新原地替换向量/属性与 PQ 编码,摘除旧边后按新向量重新接入各层。

## 使用

```bash
# 完整验收, 结果写 web/data/report.json
go run ./cmd/vecsearch bench -n 500000 -profile fast -q 40

# 构建档位: fast(M12/efc100) | balanced(M16/efc200, 默认) | quality(M24/efc200)
go run ./cmd/vecsearch bench -n 100000 -profile quality

# 启动可视化服务
go run ./cmd/vecsearch serve -n 50000 -addr :8080
# 浏览器打开 http://localhost:8080
```

常用参数: `-n` 条数、`-dim` 维度、`-ef` 查询队列大小、`-q` 每档查询数、
`-pq=false` 关闭压缩、`-out` 报告路径。

## 可视化页面

- **验收总览**: 召回/构建时间/内存 KPI、各选择率档位召回与时延、
  压缩前后对比、删除 sweep;
- **召回/时延曲线**: ef 权衡曲线、删除比例曲线;
- **过滤策略**: 各档位实际选用的策略分布、召回、P50/P95 时延、平均访问节点;
- **查询浏览器**: 交互式查询,展示 top 命中与**逐层图搜索路径**,
  红色节点表示"不满足过滤但被经过"的路由点。

## 设计取舍与已知边界

- 仿真数据为 256 个紧密高斯簇的归一化向量,簇结构明显,因此需要较大的
  `M`/`ef` 才能达到高召回——这真实反映了 HNSW 在成簇数据上的权衡,
  ef 曲线在页面上完整呈现;
- 构建为串行插入(并行两阶段方案因批内节点不可见会损害图质量,未采用),
  通过节点对距离缓存、距离循环展开、构建档位(fast/balanced/quality)
  控制大规模数据的构建时间;
- 局部图修复在每个受影响节点的**本地二度邻域**内补连(不扫描全局候选池),
  成本只与局部邻域大小成正比、不随删除总量或图规模二次方增长;实测 5 万节点
  图上删除 1 万个节点的修复在百毫秒级。实现只对**新增**删除节点修复,
  已修复的不重复计算;
- 内存估算与 Go 运行时实测堆占用都在报告的 `stats` 中给出。
